# Contributor rules

`AGENTS.md` is canonical. This reference holds database and validation details for the changes named below.

## Database operations

The SQL and change-count boundary is enforced by `tests/myco-server/db-layer.test.ts`: use the kernel's
`read`/`write`/`assertion`/`commit`/`readSet` definitions inside `db/`, returning `Bound` from family code.
Keep existing boundary allowances shrinking; remove one only after its entire file is migrated.

- Decide outcomes from a returned row or a named assertion. Match structured errors rather than fragments of messages authored by Myco.
- Fence with an assertion when the whole batch must refuse, or a conditional write with `RETURNING` when a per-row no-op is correct. New code uses neither guard tables nor fence tables nor `WeakSet` brands.
- When clearing, sealing, retiring or releasing, condition every statement on the exact identity and expected state; put the state transition last. Refusal changes nothing.
- Bind an earlier read's generation, revision or object key and recheck it in the commit.
- Every exit after an upload or claim starts leaves an owner for the work.
- A work predicate and its step share a selection function. Missing derived rows during a build do not establish that work is absent.
- Use numbered `?N` slots with labelled tuples. Shared fragments take slot names, and predicate builders receive real values.
- Generators must have runtime consumers. Move importers with a function; leave no compatibility re-export or export used only by its own file.
- Name files for their contents. Split near 300 lines by operation group. Use an options object for more than five parameters or a boolean flag.

## Schema steps

Preserve everything the running release reads: Cloudflare applies schema steps before activating the new Worker.
A step may add, but must not drop or rename a table, column, index or trigger named by the previous release
(including `INDEXED BY`) unless that code tolerates its absence. Remove it only after a release stops reading it.
Steps must resume safely after interruption, never run a statement whose cost grows with `events`, and never
rewrite every session.

`npm run check:migrations` enforces immutable shipped migrations; use a new step. The declarations gate is
`tests/meta/schema-step-ownership.test.ts`: declare dropped objects in `retires`, existing tables touched in
`reaches` (`reaching(tables, reason)` for builds, `changing(tables, reason)` for alterations, writes and drops),
and Deployment indexes in `deploymentIndexes`. Parallel unnumbered steps use `NEXT` until integration assigns a number.

For schema changes, run the populated upgrade and budget scenarios (`schema upgrade: a Deployment populated`
and `budget: populated schema upgrade`) filtered on both parity targets. Seed a changed table through its route
in `tests/parity/upgrade-seed/` if the carry refuses an empty table. A step narrowing CHECK, NOT NULL or UNIQUE
over older writers' values, or moving data out before dropping a column, needs a test at the release's shape.

## Tests and dashboard

`AGENTS.md` owns the test-behavior and budget rules; `npm run check:test-additions` enforces common violations.
Use the real schema through shared helpers, real-client headers and prerequisites, and shared constants when
testing a limit. Assert caller behavior rather than private helpers or mocked product modules. Replace obsolete
tests when replacing their contract; delete tests that merely restate implementation.

Cost tests compare the same request at two scales, on D1 without planner statistics: equal cost or a bounded
increase. Replace plan and ceiling assertions with coverage of the reads and writes they protected.

Parity scenarios belong in `tests/parity/scenarios/`, registered in `tests/parity/parity.test.ts`; standalone
parity test files are not the CI entry. Use `ageRows` from the parity harness to age rows past a TTL.
Run changed parity scenarios on the self-hosted target and also Cloudflare when target behavior differs.

Dashboard screens (`tests/ui-screens/`) run in CI and assert visible text. When changing or removing visible text,
search both that directory and `tests/myco-server-ui/` for the old text and update every expectation in the same commit.
`packages/myco/src/server-ui-assets.generated.ts` is generated by the build and test runner; never create or commit it by hand.

After changing the hook path, run `tests/meta/boundaries/hook-entry-closure.test.ts`; never raise its bundled-size ceiling.
For `check:ui` errors reaching server files, inspect dashboard imports: placeholder files holding `NEXT_*`/`LAST_*`
numbers import only other placeholder numbers. Keep schema steps and their database imports in separate files.

## Shared files and completion

Keep credentials out of output and copies. Keep real session identifiers and absolute scratch paths out of committed files.

Keep edits within the assigned ownership scope. Coordinate shared operations before changing another area's
module; new SQL still belongs in a file named for its operation, not its implementation lane.
In `scripts/test-durations.json`, edit only weights belonging to your changes. Current weight and shard policy
is in [CI](ci.md); run `node scripts/check-test-shards.mjs` after test catalogue changes.

Run `npm run check:pr` once on the final commit and paste its whole final line in the report. It includes importing
tests and generated consumers; do not run whole test directories on top. Name any shard failure that passed alone,
whether the change reaches it, checks not run and why, and CI-only coverage. The filesystem-fence-eintr and
test-temp-fence checks can fail from worktrees under `~/.local/share`; distinguish a confirmed location-dependent
failure from a change failure. Report the behavior asserted by each changed test and any unmet rule.

Hooks stay enabled for every commit, including temporary ones: neither `--no-verify` nor `core.hooksPath`
overrides nor another bypass is allowed. Verify Git author and committer identity before committing; use the
repository owner's public identity rather than a machine-local email, without changing shared Git configuration.
