Sign in, and your agents start learning

Your team's knowledge lives on a Deployment you run yourself, on Cloudflare or on your own machine. Each person installs the binary, signs in with an invite link, and connects their agents.

~/your-project
$curl --proto '=https' --tlsv1.2 -fsSL https://myco.sh/install.sh | sh $myco login <invite link> # the link your Deployment's administrator sent you; sets up your agents $myco member join # this repository now captures to the Deployment and reads from it
~
$myco server create --target local $myco server github-app --target local --url http://127.0.0.1:8787 $myco server setup-owner --target local $myco server install --target local # or on Cloudflare: myco server create --target cloudflare
~/your-project
$curl --proto '=https' --tlsv1.2 -fsSL https://myco.sh/install.sh | sh -s -- --replace-1.4 $myco login <invite link> $myco cutover --dry-run $myco cutover # every 1.4 session, spore and plan comes with you

What it does

Memory is table stakes — Myco turns it into wisdom.

Myco's own agent reads what your agents did and keeps what is worth knowing, curating it as the code moves on, then hands it back to every agent on the team.

01 · Capture

Every session reaches the team.

Your agents' hooks send each session's prompts, the work of each turn, and the plans they write to your Deployment. Nothing about the agent changes.

sessions prompts plans
02 · Learn

Sessions become spores that stay current.

Myco titles every session and draws out decisions, gotchas, discoveries, trade-offs and fixes. It supersedes what the code has moved past and consolidates what keeps coming back.

spores curation repository map
03 · Return

What one agent learns, every agent knows.

Relevant spores arrive with each prompt, and MCP tools let any agent on the team search and read everything the project knows. External agents can read it too, with an access key.

context mcp tools access keys

What agents get back

Context when it helps, and a map of your code.

Each project chooses what its agents receive. An administrator turns it on per project, on the Deployment's dashboard.

  • ✓Session-start instructions — the text your team wants every session to open with, set once on the Deployment.
  • ✓Spores with each prompt — the relevant spores an agent has not seen yet in this session, in a small budget that helps without crowding the prompt.
  • ✓The repository map — one map per project, with the layout and the files that matter, so an agent orients itself in one call.
  • ✓Seven MCP tools — search, sessions, plans, spores, the map and Myco's own run history, for any agent on the team.

Deployment

One home for your team's knowledge, run by you.

A Deployment holds your team's sessions, spores and plans, answers your agents over MCP, and schedules Myco's work. Run it on Cloudflare or on your own laptop or virtual machine.

  • ✓Hosted or self-hosted — Cloudflare's free plan with no machine to keep alive, or one binary on a laptop or small VM, with no container and no Node.js.
  • ✓Invite by link — an administrator sends a one-time link; myco login signs a machine in with it.
  • ✓Sign in with GitHub — members reach the dashboard with their GitHub account.
  • ✓Configured once — every setting lives on the Deployment, so a change reaches the whole team.
  • ✓Access keys for other agents — a hosted code reviewer can read one project and record what it found.
